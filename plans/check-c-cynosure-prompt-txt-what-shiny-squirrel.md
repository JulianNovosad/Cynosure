# Project Cynosure Development Protocol v5.3
## Context
This project simulates an advanced multi-agent Learning Structures/Graph (LRSG) system integrated with physical robot control on the AuroreMkVII platform. The core goal is to achieve robust, predictable simulation behavior and eventual hardware operability.

**Goal:** To establish a highly rigorous, multi-stage development protocol that prevents uncontrolled state drift and resource exhaustion while enabling continuous improvement through structured automation.
**Mandate Overrides (Must be followed):** The security harness (`src/harness/`) is sacred; all code must respect the physical hardware stubs and authentication protocols defined in `prompt.txt`.

## Core Operational Loop: Safe, Event-Driven Iteration
The continuous development cycle MUST NOT be a single script. It must operate as an orchestrated sequence of gated checks triggered by committed changes (PRs) or scheduled maintenance tasks.

**1. Continuous Monitoring (Scheduled/Passive):**
*   **Mechanism:** A read-only `daily_health_check.py` is scheduled to run daily at 2:00 AM.
*   **Function:** This script scans for **stale state** (e.g., old security logs, outdated progress reports) and identifies structural gaps in the codebase relative to project phases (`ROBOT_INTEGRATION_PLAN.md`). It provides a high-level risk assessment report but takes no corrective actions.

**2. Development & Testing (Active/Gate-Driven):**
*   Changes must always be submitted via Pull Requests (PRs) and pass through dedicated CI/CD pipelines (`ci.yml`, `cuda.yml`, `robot-stubs.yml`, etc.). Each workflow acts as a non-negotiable gatekeeper for quality, performance, or safety compliance.

**3. Agentic Development & Refinement:**
*   The use of advanced AI development tools, such as the **Claude Code agentic AI framework**, is intended to accelerate and assist this process. The developer must utilize these agents to analyze failure reports (e.g., test failures from `pytest`) and generate proposed fixes/implementations. Crucially, any code generated by an agent must be treated as a *draft* that requires manual review, plan writing, and explicit approval before merging.

## Key Technical Constraints & Non-Negotiables
*   **Security:** HMAC-SHA256 for all motor commands; `SecurityAuditLog` coverage on 100% of action paths.
*   **Hardware Abstraction:** All physical hardware interactions must use stubs with real interface signatures, preventing the need to change code when porting to a new device (e.g., RPi5).
*   **Aesthetics:** Frontend changes MUST pass visual convergence testing against Cyberpunk 2077 reference descriptors.

## Workflow Summary
1.  Developer makes change $\to$ Commit/PR.
2.  CI runs: `ci.yml`, `cuda.yml`, etc. (Gatekeeper).
3.  If failure occurs, the developer investigates using **Claude Code agentic AI tools** to diagnose and propose fixes.
4.  Fixes are documented in a Plan file, requiring explicit approval via `ExitPlanMode` before implementation.
5.  The system relies on *explicit user approval* at every major stage transition (plan $\to$ code $\to$ commit) to prevent autonomous runaway execution.
